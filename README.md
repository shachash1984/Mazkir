# Mazkir

A scheduling assistant for two private WhatsApp chats. It creates events in its own Outlook.com calendar and invites both configured work addresses. It also updates/cancels its events and answers agenda questions. Text/voice interpretation uses OpenAI; WhatsApp uses Baileys.

**Voice update — 14 September 2026 (local implementation; not deployed):** voice notes receive text plus an AI-generated WhatsApp voice reply. Typed messages receive text unless audio is explicitly requested. English, Hebrew, and mixed-language synthetic voice checks pass. The user selected Nova after reviewing bilingual samples; live WhatsApp audio delivery remains to be checked.

**Status:** installed at `/opt/mazkir` on the DigitalOcean Droplet `YOUR_DROPLET`. Container build, 22 offline tests, and the server demo pass. Family contacts and the user's OpenAI key are configured on the server; five synthetic OpenAI checks passed there. Microsoft organizer authorization is saved and calendar access is verified. Healthchecks accepted a diagnostic log from the Droplet; email delivery still needs testing. On 11 September 2026, the dedicated WhatsApp account was paired and the service started; reconnection from saved credentials was verified. A consistent database backup was created before startup. No real invitations have been sent. Groceries and group chats are deferred.

## Run locally

Node.js 22.12 or later is required. Commands include the experimental SQLite flag.

```powershell
npm ci
npm run check
npm test
npm run build
npm run demo
npm run setup
```

The demo uses scripted interpretation and simulated providers. It does not test the model, WhatsApp, or Outlook.

`npm run eval:live` explicitly calls OpenAI with five synthetic text cases and a $0.25 per-run reservation ceiling. The verified run recorded $0.0027; earlier diagnostic runs also consumed a small amount. It tests English, Hebrew, weekly recurrence, ambiguous cancellation, and out-of-scope requests, without any calendar or WhatsApp writes. It is not a comprehensive accuracy benchmark or a voice test.

`setup` creates `.env` with a random encryption key and preserves any existing file. Edit it locally:

| Setting | Value |
| --- | --- |
| `FAMILY_MEMBERS` | Exactly two names, international phone numbers without `+`, and work email addresses. Replace both example entries. |
| `ORGANIZER_EMAIL` | Agent's dedicated personal Outlook.com mailbox. |
| `MS_CLIENT_ID` | Microsoft application registration ID. |
| `OPENAI_API_KEY` | Key for a dedicated OpenAI project with billing enabled. |
| `HEALTHCHECK_URL` | Healthchecks.io ping URL with verified email notifications enabled. |
| `AI_MONTHLY_USD_CAP` | Application spending limit; default and maximum $8. |
| `SPEECH_VOICE` | Shared speech voice: `nova`, selected by the user for Hebrew and English. |
| `ENCRYPTION_KEY` | Generated by setup. Keep a separate private backup; never regenerate for an existing database. |

Keep keys, passwords, QR codes, and device-login codes private. `.env`, data, and backups are excluded from Git and Docker build context.

## Microsoft organizer setup

1. Create the agent's personal Outlook.com mailbox and open its calendar once.
2. Register an application in a Microsoft Entra tenant you control, supporting personal Microsoft accounts. Initial Azure/Entra tenant setup may be necessary.
3. Under Authentication, enable **Allow public client flows** for device-code sign-in. No client secret is used.
4. Add Graph **delegated** `Calendars.ReadWrite`. Put the application/client ID in `.env`.
5. Run `npm run login:microsoft` and follow the device-code instructions. Sign in as the configured agent account; the program rejects a different account.

The agent does not sign in to either work account. Whether invitations are automatically added, shown as tentative, or require acceptance depends on workplace Outlook policy. Updates and cancellations need testing on both accounts. See [MSAL token acquisition](https://learn.microsoft.com/en-us/entra/msal/javascript/node/acquire-token-requests).

## DigitalOcean deployment

Use one Ubuntu 24.04 LTS Basic Droplet with 1 GiB RAM, public-key SSH access, and the planned weekly backups. Check the checkout total against the $20 monthly budget, including tax and backup pricing. No managed database, load balancer, or public web service is needed. The app uses outbound connections and exposes no port.

Paste [deploy/cloud-init.yaml](deploy/cloud-init.yaml) into the Droplet user-data field. Add your public SSH key through DigitalOcean's key selector. Restrict inbound SSH to your IP using a DigitalOcean firewall. Cloud-init installs Docker/Compose and an SSH-only host firewall.

The current Droplet was configured over SSH with `deploy/bootstrap.sh` because cloud-init user data had not been applied. Docker, Compose, and the SSH-only host firewall are installed. The image builds and its demo runs on this 1 GiB host. Long-running workload and reboot recovery still need validation.

After cloud-init finishes, from this workspace in PowerShell:

```powershell
tar -czf mazkir-release.tar.gz src test deploy package.json package-lock.json tsconfig.json Dockerfile compose.yaml .dockerignore .env.example README.md DESIGN.md VALIDATION.md
scp mazkir-release.tar.gz root@YOUR_DROPLET:/opt/mazkir/
ssh root@YOUR_DROPLET
```

On the Droplet:

```sh
cd /opt/mazkir
tar -xzf mazkir-release.tar.gz
docker compose build
umask 077
cp .env.example .env
key=$(openssl rand -hex 32)
sed -i "s/^ENCRYPTION_KEY=.*/ENCRYPTION_KEY=$key/" .env
unset key
nano .env
mkdir -p backups
chown 1000:1000 backups
docker compose run --rm mazkir node --experimental-sqlite dist/src/cli.js login-microsoft
docker compose run --rm mazkir node --experimental-sqlite dist/src/cli.js pair-whatsapp
```

Pair using the agent's dedicated phone: WhatsApp → Linked devices → Link a device. Wait for “WhatsApp connected”, then Ctrl+C. Pair on the server; no session transfer is necessary. Pairing sessions do not execute calendar jobs.

Create a [Healthchecks.io check](https://healthchecks.io/docs/configuring_checks/) with a one-minute period and five-minute grace period. Enable and test its email integration, then set the ping URL in `.env`. Disable recovery notifications if you only want intervention alerts. No heartbeat includes family content. Pings stop when WhatsApp/Microsoft access fails, work stalls, a job blocks, or inbound storage fails. The external service can email even when the Droplet is down. Startup requires a URL but cannot verify notification settings in the dashboard.

```sh
docker compose run --rm mazkir node --experimental-sqlite dist/src/cli.js doctor
docker compose up -d
docker compose logs --tail=50
```

Stop the service before pairing, sign-in, backup, or recovery commands. One process owns the database; an ungraceful shutdown leaves a lease that expires in two minutes.

## Live acceptance checks

Use disposable events with both recipients informed; clear requests send invitations immediately.

1. Create an event from each phone. Check both Outlook recipients, title, date, duration, and Israel time. Accept invitations if workplace policy requires it.
2. From the other phone, move, rename, and cancel an event. Check both Outlook copies update without duplicates.
3. Test Hebrew, English, mixed text, and a short voice note. Check dates/transcription and a clarification for essential ambiguity.
4. Create a weekly series. Edit its next occurrence, cancel another occurrence, and edit future occurrences. Verify earlier exceptions survive and the old series ends correctly. Test an entire-series time change separately.
5. Check Israel daylight-saving dates and an explicit other time zone. Verify Outlook reminders.
6. Restart during processing. Verify no duplicate invitation. An uncertain WhatsApp acknowledgement can repeat a receipt; it must not repeat the calendar mutation.
7. Confirm an unconfigured phone and group chat cannot trigger changes and receive no response.
8. Stop the Droplet and verify an email after the monitor grace period. Reboot and check automatic startup/reconnection.
9. Restore a backup into an isolated, stopped environment. Verify decryption and inspect pending operations before enabling network processing. Never run two instances against the same accounts.
10. Measure memory and AI spending under representative traffic before treating the 1 GiB/$20 design as validated.

## Recovery and backups

```sh
docker compose stop
docker compose run --rm mazkir node --experimental-sqlite dist/src/cli.js doctor
docker compose run --rm mazkir node --experimental-sqlite dist/src/cli.js backup
# Fix account/connection problems before resuming the ID shown by doctor:
docker compose run --rm mazkir node --experimental-sqlite dist/src/cli.js resume JOB_ID
# After checking any unacknowledged inbound request with its sender:
docker compose run --rm mazkir node --experimental-sqlite dist/src/cli.js clear-inbound-fault
docker compose up -d
```

`backup` uses SQLite `VACUUM INTO` for a consistent copy. Download backups off-host and keep the encryption key separately. [DigitalOcean machine backups](https://docs.digitalocean.com/products/backups/how-to/enable/) supplement application backups. A machine backup containing `.env` also contains the key; its confidentiality depends on the cloud account.

Do not blindly start an old restored database: it may lack recently completed jobs. Reconcile the organizer calendar and queued plans first. A partial future-series operation deliberately blocks subsequent jobs until recovered.

## Behavior and limits

- Voice replies follow the message's main language or an explicit request to answer in Hebrew/English. Names and event titles retain their original language. Clear voice requests execute immediately; ambiguous ones ask a clarification.
- Incoming notes are limited to three minutes. Outgoing speech is at most one minute; long agendas get a summary of event count, busiest day, and up to two upcoming events. The full agenda arrives in text chunks. Short replies are spoken in full; an unusually long non-agenda reply uses text if it cannot fit.
- Typed requests such as “Read my agenda aloud” or “תענה בהודעה קולית” request audio for that reply. Spoken output is disclosed as AI-generated.
- Speech uses character-priced `tts-1`, mono Ogg/Opus, and the shared `SPEECH_VOICE` setting. Pricing is $15 per million input characters as checked on 14 September 2026 ([model documentation](https://developers.openai.com/api/docs/models/tts-1)). Hebrew is supported, but voices are optimized for English ([speech documentation](https://developers.openai.com/api/docs/guides/text-to-speech)); choose after listening.
- Speech shares the $8 AI cap and leaves $1 available for core requests. Generation failure, insufficient speech budget, or interrupted generation produces a text confirmation plus an audio-unavailable notice. Generated audio is cached encrypted before delivery; retries cannot rerun a calendar action. Persistent audio delivery failure falls back to text after four attempts, allowing later requests to proceed. Uncertain WhatsApp acknowledgements may still produce duplicate replies.
- `npm run eval:voice` creates six **synthetic, AI-generated** listening clips in `voice-samples/` (Nova/Onyx, English/Hebrew/mixed). It validates one voice through transcription and scheduling interpretation, plus explicit reply preferences. It makes paid OpenAI calls capped at $0.50 per run in an isolated evaluation ledger, separate from production. It never connects to WhatsApp or Microsoft. Synthetic sample files are intentionally saved locally; family voice content is not.

- Default duration: 30 minutes; default zone: Asia/Jerusalem. Both work addresses are always invited. Only the agent's own events are queried/changed; no work-calendar conflict checking.
- Recurring edits default to one occurrence. “From now on” splits the series through multiple Graph requests. It is not atomic; partial failures are saved and block later work.
- Future splits preserve captured exceptions when recurrence dates are unchanged. Changing dates/patterns with exceptions is refused. Moving entire-series dates asks for an explicit future-series request. Recurrence end dates are supported; removing recurrence is not implemented.
- Agenda queries span up to a year. Normal mutation candidates cover yesterday through 60 days ahead; request an agenda for another range first to select a distant event.
- Chat history, transcripts, and cached context expire after 30 days. Completed payloads are erased. Old unfinished jobs lose text/audio and become blocked; operational plans needed to reconcile started changes remain until completion. Routing, deduplication IDs, and usage metadata remain. Backups retain older data until deleted.
- Voice content stays in memory/encrypted database fields. No plaintext voice files are written. Inbound download/storage failures can require resending; full WhatsApp history is not imported.
- AES-256-GCM protects session tokens, payloads, history, and context in SQLite. It does not protect a compromised server holding the encryption key.
- Each AI attempt reserves spending first. Unknown outcomes retain reservations; actual usage replaces them when available. This cap excludes unrelated use of the key, cloud fees, taxes, and future provider price changes. Use a separate OpenAI project and monitor billing.
- Unofficial WhatsApp reliability, workplace invitation policy, and model interpretation accuracy remain subject to live acceptance testing.

See [DESIGN.md](DESIGN.md) for agreed scope and initial cost assumptions. Central defaults live in `src/config.ts`.
`FAMILY_MEMBERS` supports an optional `additionalEmails` array per person. Newly created events invite all unique primary and additional addresses. Existing events retain their attendees on edits and recurring-series splits.
